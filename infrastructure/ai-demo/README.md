# Isolated AWS AI demonstration

**Deployment state — 21 October 2026:** the existing isolated demonstration now
uses OpenAI Responses with `gpt-6.1-sol`. Its dedicated API-key secret stays in AWS
Secrets Manager; the viewer receives only the provider/model label. The invitation
was rotated, old sessions were rejected, and the final hosted browser gate passed
using synthetic inputs. Bedrock remains an explicit rollback/configuration option.
See [the live deployment record](DEPLOYMENT.md).

`template.json` creates a new HTTPS demonstration without changing easydicom.com,
existing distributions, Orthanc, DNS or certificates:

```text
Browser → new CloudFront distribution → private synthetic viewer S3 bucket
                                   ↘ /api/ai/* → streaming Lambda → configured provider
                                                      ↘ DynamoDB usage counters
```

The two Secrets Manager values are generated by AWS: an invitation code for human
sign-in and a separate CloudFront-to-Lambda origin secret. Neither is published in
viewer assets or CloudFormation outputs. The secret's **ARN** is an output so an
authorized administrator can retrieve the invitation privately. A CloudFront
Function overwrites the origin and client-IP context from the actual edge request.
The gateway trusts those headers only after checking the private origin secret.

The Lambda function URL uses application authentication. Its public invoke policy
is narrowly limited to URL invocation; it does not grant model access. Direct URL
requests fail the origin-secret gate, and model requests additionally require the
signed short-lived user cookie and an exact Origin match. The API cache has all
TTLs set to zero and forwards the session cookie. S3 remains private behind OAC.

## Build and provision

Install the optional server dependencies and build the clean viewer as described
in [the gateway guide](../../examples/ai-gateway/README.md), then run:

```sh
node infrastructure/ai-demo/build.mjs --viewer-dist dist --output artifacts/ai-demo
```

The output contains `gateway.zip`, its SHA256 receipt, and a separate `viewer/`
copy. The copy enables only the same-origin AI profile and refreshes its asset
inventory; normal distributable artifacts retain their default configuration.

Create a new private encrypted S3 code-artifact bucket in `us-east-1` using the
included `code-bucket.json` template (all public access blocked; versioning
enabled; deny non-TLS access):

```sh
aws cloudformation deploy --region us-east-1 \
  --stack-name easi-view-ai-demo-code \
  --template-file infrastructure/ai-demo/code-bucket.json
```

Use its `CodeBucket` output. Upload `gateway.zip` to
the SHA256-derived `codeKey` in `gateway-build.json`. Do not reuse a medical-image
bucket or place invitation files in this bucket. Then validate and deploy the
template with the bucket and immutable object key:

```sh
aws cloudformation validate-template \
  --region us-east-1 --template-body file://infrastructure/ai-demo/template.json
aws cloudformation deploy --region us-east-1 \
  --stack-name easi-view-ai-demo \
  --template-file infrastructure/ai-demo/template.json \
  --capabilities CAPABILITY_IAM \
  --parameter-overrides CodeBucket=YOUR_PRIVATE_CODE_BUCKET CodeKey=YOUR_CODE_KEY
```

The default Bedrock IAM role grants only `bedrock:InvokeModelWithResponseStream`
on the fixed regional Nova Micro model, updates to its own quota table, and writes
to its own seven-day runtime log group. Bedrock model access must be available.
OpenAI mode instead receives only `secretsmanager:GetSecretValue` on the exact
configured key-secret ARN; no wildcard secret or Bedrock invoke permission.

Upload only the verified `viewer/` output to the stack's `ViewerBucket`. Open its
`LoginUrl`, enter the privately retrieved invitation code, and run a connection
test and both tools against synthetic images and measurements. Retrieve secrets
directly into a mode-0600 private local file; never print them or include them in
logs, terminal transcripts, URLs, screenshots or repository files.


## Activate or update OpenAI after credentials and review

1. Save a valid OpenAI API key in a private mode-0600 local file outside Git. An
   existing dedicated Secrets Manager secret ARN can also be used. Never create
   an empty secret or pass the key itself as a template parameter.
2. Qualify the configured OpenAI model with only the fixed synthetic connection
   test. Store a dedicated key in Secrets Manager in the Lambda region; the secret
   value can be the raw key or JSON containing `apiKey` or `OPENAI_API_KEY`.
3. Rotate the demonstration invitation code and save it privately. Its dynamic
   reference resolves when Lambda's environment is updated. Provider/model session
   binding additionally invalidates old sessions, and the model-equality request
   header rejects stale browser profiles before secret loading or inference.
4. Build the reviewed backend and a clearly labelled OpenAI viewer variant:

```sh
node infrastructure/ai-demo/build.mjs --provider openai --model gpt-6.1-sol \
  --viewer-dist dist --output artifacts/ai-demo-openai
```

5. Upload the immutable gateway ZIP to the existing code-artifact bucket, then
   update only the owned demo stack with its new object key:

```sh
aws cloudformation deploy --region us-east-1 \
  --stack-name easi-view-ai-demo-v1 \
  --template-file infrastructure/ai-demo/template.json \
  --capabilities CAPABILITY_IAM \
  --parameter-overrides CodeBucket=YOUR_PRIVATE_CODE_BUCKET CodeKey=YOUR_CODE_KEY \
    AiProvider=openai AiModelId=gpt-6.1-sol \
    OpenAiApiKeySecretArn=YOUR_EXACT_SECRET_ARN
```

The ARN is metadata, not a credential value. Lambda receives no `OPENAI_API_KEY`
environment variable. Its lazy secret read happens only after authorized quota
admission, with an eight-second bound and at most five-minute successful cache.
Failed loads retry; they do not disable login. The secret is externally managed
and is not deleted by this stack.

6. After the stack succeeds, upload only the verified OpenAI `viewer/` variant to
   its private viewer bucket and invalidate only its distribution. Sign in with
   the new invitation, verify recipient/model labels and run both tools using
   synthetic data. Confirm old or missing model headers return `409` without
   inference. Refresh current build fingerprints and qualification receipts.

The first OpenAI activation and genuine qualification completed on 21 October
2026; repeat these checks when changing credentials or provider/model. Preserve
historical receipts rather than overwriting their provider labels. Do not reuse
old Bedrock evidence as proof of genuine OpenAI operation. To roll
back, redeploy a reviewed Bedrock configuration (`AiProvider=bedrock`), rotate the
invitation again, restore the accurately labelled Bedrock static profile and
qualify it before sharing. Keep the external OpenAI secret private; deletion or
provider-key revocation is a separate deliberate operation.

## Validation and operation

Generated tests cover protocol rejection, Origin/CSRF and session authentication,
expired/forged cookies, abuse limits, cancellation, redacted failures, output
limits, real-provider event handling, and important infrastructure properties:

```sh
node --test test/ai-gateway*.test.js test/ai-openai-provider.test.js
```

Run a local CloudFormation schema validator and security policy checker where
available, then service-side template/change-set validation. `validate-template`
alone checks template structure; it does not prove all resource properties or
deployment-time conditions. Check stack events and perform live authentication,
cache, direct-origin rejection and synthetic inference checks before sharing.

The quota table uses DynamoDB's default AWS-owned encryption key, which still
encrypts all table data at rest and requires no account-managed KMS key. See
[DynamoDB encryption](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/EncryptionAtRest.html).

The server logs only controlled diagnostic event/category/error-code fields; it
never logs bodies, headers, credentials, arbitrary upstream messages or generated
prose. When using Bedrock, review the AWS account's invocation-logging setting
separately; it is outside this stack. Operational
Lambda logs are retained for seven days. No static access logs, medical uploads,
model-managed file stores or inference-history table are created.

The default 200 admitted calls/day includes connection tests and failed or
cancelled admitted jobs; counters are intentionally not refunded. The cap bounds
model admissions rather than dollar spending. CloudFront/S3/Lambda/DynamoDB and
OpenAI inference are usage-based. The active OpenAI deployment has three Secrets
Manager secrets: two stack-generated access secrets and the separately managed
API key. Each incurs storage charges. Price the intended usage in your account
before expanding availability.

Emergency stop: set the stack's `GatewayFunctionName` reserved concurrency to
zero. Rotate the invitation by changing its Secrets Manager value **and updating
the Lambda environment** (dynamic references resolve during stack updates, not
on every request). This also invalidates existing signed sessions. Disable or
remove the isolated distribution when the demo is no longer needed. S3, the
quota table and log group are retained on stack deletion; review and remove those
separately when appropriate. Never delete an unrelated marketing resource.
